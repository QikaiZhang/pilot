# 手写、AI 与提示词

阅读顺序：

1. [spec/README.md](spec/README.md)：先按施工规格准备环境、数据和 API。
2. 本页：确定哪些代码必须手写、哪些可以让 AI 生成。
3. [repetition-lab.md](repetition-lab.md)：按类别安排每个重复逻辑的代表练习。

可脱离源码施工的最低规格见 [spec/README.md](spec/README.md)。

## 默认代码分级

| 等级 | 允许 AI 做什么 | 学习者必须做什么 |
| --- | --- | --- |
| S | 设计解释、函数签名、伪代码、测试骨架、Review | 独立实现核心正确性、并发、幂等、回退 |
| A | 提供初稿 | 改命名、字段、边界和分层，并能解释 |
| B | 直接生成脚手架 | 阅读、运行、修改少量配置 |

## 只手写 2-3 个代表样例

建议手写：

1. Redis 消息窗口裁剪和并发顺序。
2. ES 关键词/向量结果合并和去重。
3. SSE/中间件的取消、错误和资源回收。

配置、路由注册、重复 CRUD、Compose 和客户端初始化统一视为 B/A 级，生成后做 Review，不重复手写十几遍。

## 路线 A 提示词模板

```text
这是 Pilot 的 Stage XX。请只输出当前层的骨架、接口签名、测试骨架和设计检查项。
S 级核心逻辑留 TODO，不要给最终实现；A 级给可读初稿；B 级可直接生成。
先列数据流、失败路径和字段设计，再输出文件变更清单。
```

## 路线 B 提示词模板

```text
请给出可运行参考实现，但把 S 级核心逻辑用 BEGIN S_LEVEL_REFERENCE / END S_LEVEL_REFERENCE 标记。
解释后我会删除标记区域并从零重写；请同时给边界测试和 Review 清单。
```

## 每次 AI 生成后的检查

- 这段代码属于哪一层？
- 它读写了哪些数据？
- 错误、超时、取消和重复请求怎么走？
- 如果依赖不可用，是否有明确策略？
- 我能否不看代码复述它的数据流？

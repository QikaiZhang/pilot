# 测试策略

阅读顺序：

1. 先看测试分层，决定当前阶段该写哪类测试。
2. 再看手写测试优先级，只亲手完成高价值并发、RRF、SSE 取消测试。
3. 最后执行真实链路验收并填写故障记录。

## 分层

- 单元测试：纯函数、窗口裁剪、错误映射、混合检索排序。
- 集成测试：Redis、MySQL、ES 的真实协议和索引/事务行为。
- HTTP 测试：状态码、统一响应、SSE 事件、客户端取消。
- 端到端测试：聊天到历史落库的完整链路。
- 冒烟测试：Compose 启动、`/health`、`/ready`、依赖连通性。

## 手写测试优先级

先手写 3 类高价值测试：

1. 会话并发写入不会乱序或重复。
2. ES 混合检索结果稳定、去重、可解释。
3. SSE 客户端断开后模型调用和 goroutine 能停止。

重复的 DTO 校验和简单 CRUD 测试可用表驱动模板生成，但要检查断言是否真的覆盖业务规则。

## 故障记录模板

```text
故障：
现象：
影响：
Trace-ID：
定位路径：
根因：
修复：
防复发测试：
```

## 真实链路验收

在 Compose 环境中至少执行一次：健康检查 -> 知识上传 -> 关键词/向量搜索 -> Chat -> Chat History -> Prometheus 指标 -> ES 运行日志 -> Trace。测试结束清理带有唯一前缀的用户、会话和索引数据，避免下一次运行受到脏数据影响。

依赖不可用时也要测一次：Redis、MySQL、ES 各自停止，确认启动检查、运行时错误码和允许的降级行为与设计文档一致。

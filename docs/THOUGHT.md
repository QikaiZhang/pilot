# 训练思考记录

## Stage 00：训练契约

### 学习者画像

- 已熟悉 Redis 和 MySQL，参与过中小型 Go 项目。
- Go 基础、gRPC、微服务、中间件开发模式和 Elasticsearch 需要通过项目补强。

### 设计结论

- 先做单体服务，再在边界稳定后演练 gRPC/微服务。
- Redis 负责短期上下文，MySQL 负责长期事实，ES 负责搜索/日志。
- 只手写三个代表性核心：消息窗口、混合检索、SSE/中间件取消；重复样板由 AI 生成并 Review。

### 本阶段复盘题

1. 为什么完整链路优先于一次性实现所有功能？
2. 为什么 Redis 不适合作为长期唯一事实来源？
3. 哪些代码错了会影响一致性、并发或故障恢复，因此必须归为 S 级？

## 2 分钟介绍模板

Pilot 是一个用 Go 构建的运维 AI 助手。HTTP 层接收同步或 SSE 对话请求，Redis 保存短期上下文，MySQL 保存长期历史，Elasticsearch 同时承载知识库检索和运行日志；Eino 负责 Agent/工具编排，Prometheus、OpenTelemetry、Jaeger 和 Grafana 负责可观测性。我的训练重点是把一条聊天链路从设计、实现、测试到排障完整走通，并亲手实现窗口记忆、混合检索和流式取消这三个核心逻辑。

## 高频问题

### 为什么 Redis、MySQL、ES 都叫中间件？

它们都是位于业务代码和底层资源之间的通用基础设施，但职责不同：Redis 偏高速状态，MySQL 偏事务事实，ES 偏搜索和日志。中间件不是“必须写成微服务”，也可以是进程内的 HTTP 拦截器。

### 为什么先做单体，不直接做微服务？

当前主要风险是业务边界和数据流还未稳定。单体能降低网络、部署和一致性成本；等聊天、检索、观测边界稳定后，再把知识检索或观测采集拆成独立服务，才有真实的拆分依据。

### 如果拆成 gRPC 服务，先拆什么？

优先考虑知识检索服务或日志查询服务，因为它们输入输出相对稳定、资源模型独立。先定义 protobuf、超时、错误码和 Trace 透传，再做服务拆分；不要为了“用了 gRPC”而拆 Controller 和 Agent。

### ES 为什么不替代 MySQL？

ES 擅长全文/向量搜索和日志聚合，不适合作为用户、会话和消息的强事务事实来源。两者之间要通过 `doc_id`、版本和异步索引策略保持可追踪，而不是假设实时强一致。

# 开发过程思考题

这些题目来自项目中的真实取舍。每完成一个阶段，先写自己的答案，再对照实现和测试修正；不要把它们当成脱离项目的八股背诵。

## 基础与边界

- Redis、MySQL、ES 为什么都可以被称为中间件？它们和 HTTP 中间件分别处在哪一层？
- 为什么先做单体，再考虑 gRPC/微服务？什么信号说明边界已经稳定？
- 配置、依赖初始化和业务对象为什么要分开？启动失败与运行时降级如何区分？

## 记忆与一致性

- 短期记忆为什么放 Redis，长期历史为什么放 MySQL？
- TTL、窗口裁剪、并发追加、重复请求和大 key 分片分别解决什么问题？
- Redis 读失败、MySQL 写失败时，用户看到什么，系统如何补偿？
- SSE 为什么在流结束后再保存 assistant 消息？中途断开应该保存什么？

## HTTP、SSE 与安全

- 同步和流式接口如何复用业务编排而不复制造成漂移？
- 参数规范化、统一错误码、Bearer/X-API-Key、CORS 和 IP 限流分别保护什么？
- 客户端断开后，context 如何一路传到模型和工具？

## RAG 与 ES

- BM25、向量召回、RRF 各自解决什么问题？为什么不能直接相加两种分数？
- `text`、`keyword`、`dense_vector` 字段如何选择？向量维度变更如何迁移？
- 文档如何切块、去重、版本化和防止越权？检索内容如何防 Prompt 注入？
- ES 作为搜索索引时，MySQL/对象存储中的事实来源是什么？

## Agent 与微服务

- Graph 节点为什么要有明确的输入输出和超时？
- 工具失败、模型规划失败、达到最大步数时分别如何停止？
- 如果拆成 gRPC，如何定义 protobuf、错误码、超时、重试和 Trace 透传？

## 可观测性与测试

- Trace、Metric、Log 如何通过同一个 request context 关联？
- 为什么指标标签必须低基数？异步日志队列满时为什么允许丢日志，如何告警？
- 如何用一条 E2E 测试证明 Redis、MySQL、ES、Prometheus 和 Trace 真的接通？

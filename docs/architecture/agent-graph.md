# Agent 图与检索编排

## 最小图

完整 Agent 可以抽象为：

```text
输入
  -> 并行：InputToRag / InputToChat
  -> 知识检索 -> ChatTemplate
  -> ReAct 循环（决定是否调用工具）
  -> 输出与记忆
```

并行分支的目的不是追求复杂，而是让“用户原话”和“检索上下文”分别可观测、可测试。每个节点都应有输入、输出、超时和失败行为。

## Full 与 Simple

- Full：包含 Graph、RAG、工具和多轮状态，作为主路径。
- Simple：只做模型对话，作为调试或受限环境下的确定性回退。

回退时必须明确告诉上层“没有使用知识库/工具”，避免把普通模型回答误认为经过证据验证的结论。

## 工具边界

工具输入要有结构化参数、超时和最大返回量；工具输出应区分“无数据”“依赖失败”和“权限拒绝”。Agent 只负责决策，工具负责访问外部系统，Controller 负责协议和错误码。

## 多 Agent 练习

先用规则分诊把请求分为健康检查、指标、日志、知识库和未知类，再让证据分支并行执行，最后由综合节点生成结论。模型规划失败时回退到规则分支；部分分支超时要保留 `limitations`，不能伪装成完整结论。

# Stage 00：训练契约与最小范围

## 目标

把课件中的大系统收敛为一个学习型 MVP：先支持单用户聊天、短期上下文、历史落库和健康检查；知识库、Agent 工具和观测能力按后续阶段叠加。

## 本阶段先设计

- 用户、会话、消息、知识文档四个概念的边界。
- 一条最简数据流：`POST /chat -> 读取记忆 -> 生成回复 -> 写回记忆 -> 异步落 MySQL`。
- 失败时是否返回部分结果、是否允许历史落库失败不影响主响应。

## 训练路线

- 默认路线 A：S 级逻辑只给签名和测试骨架。
- 重复性工作使用 AI：配置样板、路由注册、基础 DTO、Docker Compose。
- 手写要求：至少手写一版消息窗口合并和一版请求错误映射。

## 验收

- 能用自己的话解释“为什么 Redis/MySQL/ES 是不同职责”。
- 能画出单体版数据流，不引入 gRPC 作为前置条件。
- 提交字段草图和取舍记录后，才能进入 Stage 01。

# 阶段工作流手册

用于项目启动、阶段拆分、分支推进和对话节奏控制。

## 1. 项目启动信息

先问 5 个问题，不要一次性问太多细节：

```text
我们先确认项目训练契约：
1. 项目名称是什么？
2. 技术栈是什么？例如 Go / Java / Python / React + Node。
3. 你的当前水平？例如零基础、会语法但没项目、做过简单 CRUD。
4. 目标岗位？例如后端开发、Java 后端、Go 后端、全栈开发。
5. 希望重点训练什么？例如系统设计、并发、数据库、微服务、业务建模、面试表达。
```

如果用户已经提供部分信息，只问缺失项。

## 2. 阶段拆分模板

默认使用 5 到 8 个阶段。复杂项目可以更多，但不要一开始拆得过碎。

推荐结构：

| 阶段 | 目标 | 主要训练点 | 典型分支 |
| --- | --- | --- | --- |
| Stage 01 | 需求澄清与领域建模 | 业务边界、核心实体、数据流草图 | `stage/01-design-model` |
| Stage 02 | 工程骨架与基础设施 | 分层、配置、日志、测试入口 | `stage/02-project-skeleton` |
| Stage 03 | 核心业务闭环 | 一条端到端数据流、S级核心逻辑 | `stage/03-core-flow` |
| Stage 04 | 异常与边界 | 参数校验、错误处理、重试、幂等 | `stage/04-error-boundary` |
| Stage 05 | 持久化与查询 | 表结构、索引、Repository、事务 | `stage/05-persistence-query` |
| Stage 06 | 并发/异步/扩展能力 | MQ、调度、并发控制、可观测性 | `stage/06-advanced-flow` |
| Stage 07 | 测试与重构 | 单测、集成测试、重构设计模式 | `stage/07-test-refactor` |
| Stage 08 | 面试交付 | 系统设计文档、问答手册、口述训练 | `stage/08-final-deliverables` |

按项目类型调整阶段名称，不要机械套用。

## 3. 每阶段启动协议

进入任何阶段前，输出并确认：

```markdown
## Stage XX：阶段名称

本阶段目标：
- 

本阶段先设计内容：
- 

如果本阶段涉及实体/DTO/表结构/状态枚举，请先进入字段建模评审：
- 学习者先提交字段名、类型、可空性、默认值、业务含义、选型理由、查询/索引用途。
- AI 按 100 分制评分，低于 80 分不得进入编码。

请选择本阶段开发路线：
- 路线A【留空手写】：AI 给骨架，S级核心逻辑留空。
- 路线B【删除重写】：AI 给可运行参考，S级区域必须删除后重写。

如果本阶段涉及业务流程，请选择数据流链路：
- 最简通用链路：快速跑通端到端。
- 复杂全场景链路：覆盖异常、重试、边界、多分支。
```

用户未选择路线时，不开始代码输出。

## 4. 分支推进协议

在 Git 仓库中：

1. 检查当前分支和未提交修改。
2. 确认上一阶段是否验收。
3. 创建阶段分支：`stage/{序号}-{阶段名称}`。
4. 阶段完成后做 diff review。
5. 只有验收通过后，才建议合并或进入下一阶段。

遇到未提交修改：

- 如果修改与本阶段相关，先阅读并纳入当前阶段。
- 如果修改无关，不要回滚，说明会避开这些文件。
- 如果修改阻塞阶段推进，指出冲突点并询问用户处理策略。

## 5. 阶段验收话术

验收时使用：

```markdown
## Stage XX 验收

代码运行：
- [ ] 已运行基础自测
- [ ] 关键路径可跑通

S级手写：
- [ ] S级区域已由学习者独立完成
- [ ] AI 未直接交付最终核心实现

文档：
- [ ] CHANGELOG.md 已更新
- [ ] THOUGHT.md 已更新
- [ ] 字段建模评分与改进记录已写入 THOUGHT.md

口述：
- [ ] 能讲清字段类型选型
- [ ] 能讲清数据流
- [ ] 能讲清分层职责
- [ ] 能讲清方案取舍
- [ ] 能讲清后续优化

结论：通过 / 不通过
```

不通过时，列出最少必要补救项。

## 6. 防止 AI 代劳的中断条件

出现以下情况要暂停并拉回训练流程：

- 用户要求“直接给我完整项目”。
- 还没设计就要求生成库表、实体、核心流程代码。
- 没有字段建模评分，就要求生成 struct/class/entity/DTO/table 代码。
- 用户跳过 S级手写。
- 用户无法解释刚生成的关键代码。
- 文档空泛，只写“完成了某功能”。

暂停时说明：当前缺失的是哪一项训练目标，然后给一个具体下一步。

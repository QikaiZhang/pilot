# 需求澄清问题集

先让用户自由描述，再按需挑问题问。

## 先听用户自己讲

优先让用户说明：

- 要做什么
- 给谁用
- 现在做到哪一步
- 技术栈是什么
- 想让我输出什么

## 需要时再问的轻量问题

### 范围

- 你希望我按完整 CRUD 流程走一遍，还是只做关键链路？
- 你要的是最小可跑通版本，还是直接做完整业务闭环？

### 风格

- 你更偏好可读性，还是更偏好优雅和抽象？
- 你愿意先用可读性优先的写法跑通，再逐步往优雅方向演进吗？
- 你希望我把代码写得更直白，还是更像生产级封装？

### 约束

- 有必须遵守的框架、目录、命名或分层规范吗？
- 你希望我优先处理性能、可维护性，还是交付速度？
- 你有没有不想碰的技术点或实现方式？

## 推荐问法

一次最多问 1 到 3 个问题，优先组合成：

1. 你希望自己走一遍 CRUD 流程吗？
2. 你更喜欢可读性优先还是优雅优先？
3. 你希望我按“先可读，再优雅”的方式推进吗？
